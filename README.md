# wb_analytics

Локальная панель продавца Wildberries: актуальная лента заказов через `POST /api/analytics/v1/order-feed`, сборка новых заданий FBS с поставками и грузоместами, остатки FBS по складам и товарам, баланс кабинета и история его изменений, статусы и действия FBS, воронка продаж, подробная аналитика рекламы, несколько кабинетов и универсальная консоль WB API.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. Укажите `WB_TOKEN_1`. Для дополнительных кабинетов добавьте `WB_TOKEN_2`, `WB_TOKEN_3` и так далее.
3. У токена должны быть включены нужные категории: минимум «Маркетплейс», «Статистика», «Аналитика», а для рекламной вкладки — «Продвижение».
4. Запустите `npm start` и откройте `http://localhost:4173`.

Имена из `WB_CABINET_N_NAME` можно менять в интерфейсе. Переименования сохраняются локально в `data/cabinets.json`. Токен никогда не отправляется в браузер.

## Методы WB

Готовый интерфейс использует актуальные методы FBS, аналитическую Ленту заказов и воронку v3. Лента показывает оформление, выкуп и отмену, а период строится по времени обновления события. Раздел «API-консоль» поддерживает любой документированный путь на разрешённых официальных доменах WB. Это даёт доступ к методам контента, цен, маркетплейса, статистики, аналитики, рекламы, отзывов, чатов, возвратов, документов, финансов, тарифов и пользователей без хранения отдельных токенов в приложении.

Вкладка «Реклама» использует `GET /api/advert/v2/adverts` и `GET /adv/v3/fullstats`. Она показывает расходы и рекламную выручку по дням, CTR, CPC, CPM, CR, ДРР, ROAS, платформы, кампании и товары. Из-за ограничения WB API период рекламной статистики не может превышать 31 день.

Вкладка «Новые заказы» работает со сборочными заданиями FBS. Список приходит из `GET /api/v3/orders/new` и связывается с карточками товаров, чтобы показать фото, название, артикул продавца, категорию, размер и баркод. Выбранные задания собираются в поставку: можно указать одну из открытых поставок или создать новую, после чего каждое задание добавляется методом `PATCH /api/v3/supplies/{supplyId}/orders/{orderId}` и переходит в статус «на сборке».

Поставками управляет отдельная панель: создание (`POST /api/v3/supplies`), удаление, просмотр состава (`GET /api/v3/supplies/{supplyId}/orders`) и передача в доставку (`PATCH /api/v3/supplies/{supplyId}/deliver`). Грузоместа создаются через `POST /api/v3/supplies/{supplyId}/trbx`, заполняются выбранными заданиями через `PATCH /api/v3/supplies/{supplyId}/trbx/{trbxId}` и удаляются при необходимости.

Стикеры товаров запрашиваются через `POST /api/v3/orders/stickers` пачками по 100 заданий — это ограничение WB API. QR-код поставки приходит из `GET /api/v3/supplies/{supplyId}/barcode`, QR-коды грузомест — из `POST /api/v3/supplies/{supplyId}/trbx/stickers`. Любой набор можно сохранить файлами или открыть страницей печати с раскладкой 58x40 мм — по одному стикеру на лист.

Вкладка «Остатки FBS» получает склады через `GET /api/v3/warehouses`, остатки — через `POST /api/v3/stocks/{warehouseId}`, и связывает `chrtId` с карточками товаров для отображения артикула продавца, `nmId`, категории, размера и SKU.

Опасные изменяющие запросы в консоли требуют явного подтверждения. Реальные возможности токена определяются категориями, выбранными при создании токена в кабинете WB.
