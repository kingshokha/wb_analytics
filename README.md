# WB Pulse

Локальная панель продавца Wildberries. Сайт работает на вашем компьютере: сервер `server.js` ходит в API WB с токенами из `.env`, а страницы в папке `public/` показывают данные. Токен никогда не уходит в браузер. Поддерживается несколько кабинетов.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. Укажите `WB_TOKEN_1`. Для дополнительных кабинетов добавьте `WB_TOKEN_2`, `WB_TOKEN_3` и так далее, названия — в `WB_CABINET_N_NAME` (их можно менять и в интерфейсе, переименования хранятся в `data/cabinets.json`).
3. У токена должны быть включены категории «Маркетплейс», «Статистика», «Аналитика», «Цены и скидки», «Контент» и «Продвижение». Чтобы менять карточки товаров, у категории «Контент» нужен уровень «Чтение и запись». Для раздела «Сообщения» нужны «Вопросы и отзывы», «Чат с покупателями» и «Возвраты покупателями» (для ответов — с записью).
4. Запустите `npm start` и откройте `http://localhost:4173`. Нужен Node.js 20 или новее.

Без токенов сайт показывает демонстрационные данные (`WB_DEMO_MODE=true`). Тесты: `npm test`.

## Разделы

Меню слева одно на все страницы (`public/sidebar.js`). Сводка, реклама с детализацией кампании и воронка сами обновляются раз в 2 минуты, пока вкладка открыта.

| Раздел | Что показывает |
|---|---|
| **Сводка** | Главное за период в сравнении с прошлым периодом той же длины: заказы и выкупы, переходы и конверсия из воронки, расходы на рекламу и ДРР, график по дням, доли товаров, товары с просадкой на 30% и больше. |
| **Лента заказов** | Оформление, выкуп и отмена из аналитической ленты заказов (`POST /api/analytics/v1/order-feed`). |
| **Новые заказы** | Сборочные задания FBS: сборка в поставку, поставки и грузоместа, передача в доставку, стикеры (по одному на лист 58×40 мм). На пункте меню — число новых заданий. |
| **Остатки FBW / FBS** | Остатки по складам и товарам. После изменения остатков FBS (задать, скопировать на склады, шаблон) список не перезагружается: у WB перечитываются только изменённые позиции. На «Остатках FBS» кнопка «История остатков» (по Google Таблице): обнуления — какой товар на каком складе был на нуле и сколько времени; товары за период — сейчас, минимум, ушло, пополнено, обнуления (строка раскрывается по складам и дням); итоги по дням. Только выбранный кабинет (сопоставляется с кабинетом таблицы по названию). |
| **Возвраты** | Возвраты покупателей. |
| **Цены и скидки** | Цены всех товаров кабинета с фильтрами, сохранёнными наборами и изменением цен. Цены и остатки показываются по ходу загрузки: строки — сразу, названия и фото — по мере загрузки карточек. Клик по товару открывает окно цены: история из Google Таблицы за 7, 14, 30 дней или всё время — с момента, когда товар появился в таблице (или когда таблица начала вести цены кабинета), с разрывом, пока товара в ней не было; сводка (сколько держится текущая цена, минимум, максимум, число изменений), линии «Цена до скидки» и «Цена в WB Клубе» по кнопкам, заказы по дням под графиком (из воронки). Время в истории — когда таблица заметила изменение (она проверяет цены раз в час). Подсказка — мышью, касанием или стрелками с клавиатуры. |
| **Карточки товаров** | Все карточки кабинета с фильтрами (предмет, бренд, ярлык, «что проверить»: без фото, короткое описание, габариты; «документы»: без КИЗ Честного знака, проверка не пройдена, на проверке, какого документа нет, причина ошибки — с числом карточек; «склейка»: со склейкой — карточки одной группы подряд под строкой группы, без склейки), при выбранном предмете — галочки у карточек без склейки («Выбрать все» — все по фильтрам на всех страницах, Shift+клик — диапазон) и «Объединить по 30 шт»; без предмета — «Склеить по 30…» сразу по всем предметам (каждый отдельно). В окне склейки: «похожие по названию» (одинаковое название без учёта регистра и знаков; карточка без пары остаётся одна) или «подряд по таблице» (63 → 30 + 30 + 3), «дополнять неполные склейки до 30»; план показывается до отправки, шаги уходят в WB по очереди в пределах лимита (на 429 — повтор), есть «Остановить»; уже склеенные карточки не трогаются), корзина с восстановлением, ошибки сохранения, ярлыки продавца. Список карточек хранится на диске (`data/Cards/`): раздел открывается сразу с сохранённым списком, свежий грузится из WB в фоне и подменяется сам; при самой первой загрузке карточки показываются по ходу. Карточка открывается на отдельной странице (`card.html`): наименование, бренд, артикул, описание, характеристики предмета, габариты, размеры и баркоды, документы, маркировка — одним сохранением в WB; фото, ярлыки, склейка («Добавить в карточку другие товары» — сразу несколько карточек того же предмета, до 30 в группе; «Выбрать все» — несклеенные до лимита, «Склеенные» — показать карточки из других склеек) и корзина — отдельными действиями. Создавать карточки сайт не умеет. Серверная часть — `content-cards.js`. |
| **Воронка** | Воронка продаж v3 по товарам. Таблица товаров собирается по 1000 штук и показывается по ходу загрузки; готовая таблица периода хранится в `data/Funnel/<кабинет>/tables/` и при повторном открытии показывается сразу. Стрелка у товара открывает **детализацию товара** (`product.html`): органика и реклама по дням, мини-графики, флажки запуска и остановки рекламы (кликабельные; с начала отслеживания в Google Таблице — по статусу и составу кампании, раньше — по 50 показам в день), флажки изменения цены из Google Таблицы, свои отметки. |
| **Оценки товаров** | Рейтинг продавца и товаров, число отзывов по звёздам и их динамика за период. |
| **Реклама** | Расходы и рекламная выручка по дням, CTR, CPC, CPM, CR, ДРР, ROAS, кампании с числом активных артикулов, товары (квадрат со стрелкой — детализация товара, название — товар на WB). Кампания открывается в **детализации кампании** (`campaign.html`): остаток бюджета перед кнопкой паузы (при наведении — на сколько хватит по средним затратам за 7 дней, меньше чем на день — красным) и «+» — пополнение бюджета с единого счёта, счёта продвижения или бонусов; переключатель «Все / Поиск / Рекомендации» слева от периода меняет только карточки показателей (поиск — вместе с каталогом, рекомендации — полки; по данным расширения о зонах показов, без отмен); график по датам (наведение выделяет линию, легенда скрывает и показывает линии; флажки ▶ запуска и ■ остановки — как в детализации товара, по дням работы, при наведении заливается период работы; флажки изменений из Google Таблицы: название, места показа, состав, ставки, минус-фразы, цены товаров кампании), мини-графики, статистика по дням и зонам показов (поиск, полки, каталог; по всем артикулам, по одному или «другие товары» — заказы после клика; см. ниже), товары, ключевые слова с исключением (фильтр «Все / Активные / Исключённые»), переименование, заметки, кнопка «История» (изменения из Google Таблицы). |
| **Дела** | Список задач выбранного кабинета (новое дело получает его): тип, приоритет, артикул, архив и журнал по каждой задаче. |
| **Сообщения** | Кнопка слева от колокольчика (на ней — сколько ждёт ответа). Общение с покупателями выбранного кабинета: чаты (переписка, ответ с файлами JPEG, PNG, PDF; «ждёт ответа» — покупатель написал последним не раньше 10 дней назад), вопросы (ответить, изменить ответ, отклонить), отзывы (без ответа, с ответом, архив; ответить, изменить ответ, запросить возврат товара), заявки на возврат за 14 дней (решения из вариантов WB). Серверная часть — `communications.js`. |
| **История изменений** | Изменения выбранного кабинета из Google Таблицы за период (свой у раздела, по умолчанию последние 14 дней): цены (изменение цены — в рублях и процентах), кампании, ставки, минус-фразы, остатки. Кабинет сопоставляется по названию без номера в начале. Цена в WB Клубе, совпадающая с ценой со скидкой, отдельной строкой не показывается. Фильтры по разделу и виду изменения и поиск. Кампании и товары — ссылками на их детализацию. |
| **Цены Сималенда** | Не зависит от кабинета WB. Раз в час сервер берёт список артикулов из отдельной Google Таблицы ([google-sheets/sima-land/README.md](google-sheets/sima-land/README.md)), загружает их оптовые цены из API Сималенда и записывает в таблицу. Сималенд не пускает запросы с серверов Google, поэтому загружает компьютер с сайтом; пока он выключен, цены не обновляются. Раздел показывает историю: цена и цена по акции «Опт» (изменение — в рублях и процентах), добавленные и убранные артикулы, товары, которых нет на Сималенде. Устроен как «История изменений»: дни, поиск по артикулу и названию, вид изменения, свой период (по умолчанию 14 дней). Товар — ссылкой на Сималенд. Кнопка «Загрузить цены сейчас» — не дожидаясь часа. Серверная часть — `sima-land.js`, копия на компьютере — `data/Sima/`, в `.env` — `SIMA_SHEET_URL`, `SIMA_SHEET_KEY` и необязательный `SIMA_TOKEN`. |
| **Прибыль Сималенда** | Товары выбранного кабинета, у которых артикул продавца начинается с артикула Сималенда (`6938164/125/ШДФ`) или это артикул Lenardi (`305-043/L`), — как таблица «Артикулы … с логистикой»: цена на WB (со скидкой продавца), закупка по оптовой цене поставщика или обычной цене Сималенда (Сималенд — последняя загрузка, `data/Sima/prices.json`; Lenardi — отчёт xlsx с колонками «Артикул» и «Опт.», загруженный кнопкой «Загрузить опт Lenardi», цены — `data/Sima/lenardi.json`, сами файлы — копиями в `data/Sima/Lenardi/`, модуль `lenardi.js`), комиссия WB по модели FBS для предмета, налог, сборка, логистика по объёму упаковки (тариф WB «Свой склад РФ», до литра — по ступеням), чистая прибыль в рублях и процентах от цены, цена для желаемой прибыли и отличие от текущей. Желаемая прибыль, налог, сборка и вид закупки задаются над таблицей и запоминаются в браузере. Отбор: поставщик; убыток, прибыль ниже или не ниже желаемой, нет оптовой цены, нет в списке поставщика (на листе «Артикулы» таблицы Сималенда или в файле опт Lenardi), нет в наличии на Сималенде. «Скачать для Excel» — отобранные товары с расчётом в CSV. «Применить цены» — выбранным галочками товарам (или всем отобранным) ставит цену со скидкой, равную цене для нужной прибыли: скидка продавца не меняется, пересчитывается цена до скидки; снижение больше 30% — ступенями по 30% за загрузку (иначе WB отправит в карантин или не примет), с проверкой каждой загрузки в WB. Перед загрузкой прежние цены сохраняются в `data/Sima/Откаты цен/` (CSV, файлы не удаляются). Окно показывает ход, итог и товары, которые WB не принял. Серверная часть — `sima-profit.js`. |

Период во вкладке «Реклама» и рекламы в сводке — не больше 31 дня: это ограничение WB API.

## Google Таблица

Таблица сама раз в час берёт из API WB цены, кампании, ставки, минус-фразы и остатки и записывает каждое изменение в историю. Подключение и листы описаны в [google-sheets/README.md](google-sheets/README.md).

Сайт читает историю через веб-приложение скрипта: `WB_SHEET_URL` и `WB_SHEET_KEY` в `.env`. Копия истории хранится на компьютере в `data/Sheet/` — у каждого кабинета таблицы своя папка: `data/Sheet/<кабинет>/<раздел>/<ГГГГ-ММ>.json`. Старые общие файлы, где кабинеты лежали вместе, при первом запуске раскладываются по кабинетам и целиком переезжают в `data/Sheet/_Все кабинеты вместе (до разделения)/` — ничего не удаляется. Копия дозагружается через 20 секунд после запуска сервера, раз в час и при открытии окна истории. Окна истории и раздел «История изменений» сначала показывают копию с компьютера, потом новые строки из таблицы.

## Статистика по зонам показов

В открытом API WB статистики по зонам показов нет. Её присылает расширение Chrome «WB: статистика по зонам показов» (папка расширения лежит вне проекта). Откройте кампанию в кабинете cmp.wildberries.ru, нажмите на расширение, выберите период и «Загрузить». Расширение покажет таблицу и отправит данные на `http://127.0.0.1:4173/api/advertising/campaign/zones`. Сайт сам найдёт кабинет по номеру кампании и сохранит данные в `data/Ads/<кабинет>/<кампания>/zones.json`. Присланный день заменяет тот же день свежими цифрами, остальные дни остаются. Принимаются только запросы от расширения или с самого сайта.

## Данные на компьютере

Всё лежит в `data/` и не попадает в git:

- `cabinets.json`, `balance-history.json` — названия кабинетов и история баланса;
- `price-presets.json`, `stock-presets.json`, `keyword-tags.json` — сохранённые наборы и метки;
- `campaign-notes.json`, `product-notes.json`, `todos.json` — заметки и дела;
- `Cards/<кабинет>/` — карточки кабинета по предметам: файл на каждый предмет («Худи (12).json», в скобках — сколько карточек; изменилось число — файл переименовывается) и `index.json` со временем загрузки, списком файлов и номерами предметов (названия и фото для всех разделов; перезаписываются свежими из WB);
- `Ads/`, `Funnel/`, `Photos/` — кэш рекламной статистики (и `zones.json` — зоны показов от расширения), воронки и фото;
- `Sheet/` — копия Google Таблицы;
- `Chats/` — переписка из чатов с покупателями (дочитывается с последнего сохранённого события).

## Изменяющие действия

Сайт может менять данные в WB: цены, остатки FBS, бюджет кампании (пополнение), поставки и грузоместа, исключение ключевых слов, название кампании, данные карточек товаров (а также их фото, ярлыки, объединение, корзину), сообщения и ответы покупателям, решения по заявкам на возврат. Каждое такое действие требует явного подтверждения в интерфейсе.
