# Правила проекта

## Уведомления — только выбранного кабинета

Любая новая функция или доработка, которая пишет в колокольчик (`setNotices`, `addNotice` в `public/notifications.js`), должна показывать в уведомлениях только информацию кабинета, выбранного на сайте:

- данные для уведомления берутся только по текущему кабинету (`state.cabinet`); данные Google Таблицы — с параметром `cabinet` (сервер сопоставляет кабинет таблицы по названию);
- нельзя собирать уведомление по всем кабинетам сразу и нельзя упоминать в нём другие кабинеты;
- если ответ пришёл после переключения кабинета, уведомление не записывается;
- после переключения кабинета колокольчик показывает уведомления нового кабинета.

## Методы WB API

Прежде чем добавить новый метод WB API или изменить работу с уже используемым, внимательно изучи этот метод в документации https://dev.wildberries.ru/docs/openapi/:

- примеры запроса;
- примеры ответа, в том числе ответы с ошибками;
- query Parameters, path Parameters и заголовки;
- Request Body Schema;
- Response Schema;
- лимиты запросов и требования к токену.

Код пиши по документации, а не по догадке. Названия полей, типы, обязательность, допустимые значения и лимиты бери из схем. Если документация расходится с реальным ответом WB, опирайся на реальный ответ и напиши об этом в комментарии в коде.

Страницы документации на сайте отвечают ошибкой 498. Поэтому бери спецификацию в YAML: `https://dev.wildberries.ru/api/swagger/yaml/ru/<файл>.yaml`. Файлы названы по-старому, например «Работа с товарами» (item-management) — это `02-items.yaml`.
